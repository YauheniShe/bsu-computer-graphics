# Формулы и подготовка к защите

## Что означают компоненты

**RGB** — аддитивная модель, то есть сложение света. R — красный, G — зелёный, B — синий. В интерфейсе каждая компонента находится в диапазоне 0–255. `(0, 0, 0)` — чёрный, `(255, 255, 255)` — белый. Перед вычислениями значения делятся на 255.

**CMYK** — субтрактивная модель: голубая (C), пурпурная (M), жёлтая (Y) и чёрная (K) краски поглощают части падающего света. В интерфейсе используются проценты 0–100. В учебной модели без красок получается белый, а при K=100% — чёрный. Реальная печать зависит от красок, бумаги и цветового профиля; используемая формула этого не моделирует.

**HLS** — представление через цветовой тон (H), светлоту (L) и насыщенность (S). H задаётся углом 0–360°: 0° — красный, 60° — жёлтый, 120° — зелёный, 180° — голубой, 240° — синий, 300° — пурпурный. L и S задаются в процентах. При L=0% цвет чёрный, при L=100% — белый. При S=0% цвет серый. Названия HLS и HSL обозначают одну модель с разным порядком координат; в этой работе порядок **H, L, S**.

У HSV другая третья характеристика — V, максимум RGB-компонент. В HLS светлота равна полусумме максимума и минимума. Например, у чистого красного L=50%, а V=100%.

## RGB → CMYK

Нормируем RGB:

```text
r = R / 255; g = G / 255; b = B / 255
v = max(r, g, b)
k = 1 - v
```

Если `v = 0`, это чёрный: `(c, m, y, k) = (0, 0, 0, 1)`. Отдельная ветка нужна, чтобы избежать деления на ноль.

Иначе:

```text
c = (1 - r - k) / (1 - k) = 1 - r / v
m = (1 - g - k) / (1 - k) = 1 - g / v
y = (1 - b - k) / (1 - k) = 1 - b / v
```

Для интерфейса все четыре значения умножаются на 100. В коде используется правая форма выражений, чтобы не вычитать близкие числа лишний раз.

## CMYK → RGB

Сначала делим проценты CMYK на 100:

```text
R = 255 × (1 - c) × (1 - k)
G = 255 × (1 - m) × (1 - k)
B = 255 × (1 - y) × (1 - k)
```

Пример: `(C, M, Y, K) = (50, 50, 50, 50)` даёт `(R, G, B) = (63.75, 63.75, 63.75)`.

Соответствие неоднозначно: `(0, 0, 0, 75)` даёт тот же RGB. Поэтому ввод CMYK нельзя немедленно заменять результатом цепочки CMYK → RGB → CMYK: ползунки неожиданно «прыгнут». `ColorState` сохраняет исходные CMYK и пересчитывает только две другие модели. Когда источником становится RGB или HLS, CMYK вычисляется по формуле с максимальным выделением чёрного.

## RGB → HLS

Работаем с `r, g, b` в диапазоне 0–1:

```text
v = max(r, g, b)
n = min(r, g, b)
d = v - n
l = (v + n) / 2
```

Если `d = 0`, цвет ахроматический: `s = 0`. Тон не определён, и преобразование условно возвращает `h = 0`. Это также обрабатывает чёрный и белый без деления на ноль.

Иначе:

```text
s = d / (1 - |2l - 1|)

если v = r: h = 60 × (((g - b) / d) mod 6)
если v = g: h = 60 × ((b - r) / d + 2)
если v = b: h = 60 × ((r - g) / d + 4)
```

Возвращаем `(h, 100l, 100s)`. Модуль в первой ветке приводит отрицательный угол к диапазону 0–360°.

## HLS → RGB

H оставляем в градусах, L и S делим на 100:

```text
q = (H mod 360) / 60
c = (1 - |2l - 1|) × s
x = c × (1 - |(q mod 2) - 1|)
m = l - c / 2
```

`c` — разность максимальной и минимальной нормированных RGB-компонент (chroma), `q` выбирает один из шести секторов цветового круга.

| Сектор q | Временные (r′, g′, b′) |
|---|---|
| [0, 1) | (c, x, 0) |
| [1, 2) | (x, c, 0) |
| [2, 3) | (0, c, x) |
| [3, 4) | (0, x, c) |
| [4, 5) | (x, 0, c) |
| [5, 6) | (c, 0, x) |

```text
R = 255 × (r′ + m)
G = 255 × (g′ + m)
B = 255 × (b′ + m)
```

Углы 0° и 360° совпадают. Если пользователь вводит HLS с нулевой насыщенностью или крайним L, исходные HLS сохраняются — можно сначала выбрать тон у чёрного цвета, затем увеличить L и увидеть выбранный цвет.

## Как работает программа

1. Пользователь меняет поле, ползунок или точку на палитре.
2. Обработчик вызывает `ColorState.set_component()` либо `set_values()`.
3. `set_values()` проверяет диапазоны и конечность чисел. `nan` и бесконечность не допускаются. При ошибке прежнее состояние остаётся целым.
4. Исходная модель переводится в RGB. Через RGB вычисляются две другие модели. Это позволяет не писать отдельные формулы CMYK ↔ HLS.
5. `ColorApp.refresh()` обновляет виджеты и образец. Флаг `ModelPanel.updating` не даёт программному обновлению поля или ползунка повторно запустить обработчик ввода.
6. Положение маркеров меняется сразу, растры палитр обновляются по таймеру. При неизменных фиксированных компонентах используется уже готовое изображение.

У палитры выбираются две компоненты. Координаты точки линейно переводятся в их диапазоны. Остальные компоненты берутся из текущего состояния. Для каждого пикселя палитры получается набор координат модели, затем его RGB. PPM-изображение создаётся средствами стандартной библиотеки и показывается `tkinter.PhotoImage`.

## Точность

Внутренние значения — `float`. Их не округляем между преобразованиями. Подписи округляются до двух знаков, HEX и экранные пиксели — до целых 0–255. Именно поэтому изменение одной компоненты берёт остальные из `ColorState`, а не считывает уже округлённый текст соседних полей.

Тесты проверяют сохранение цвета после многократных преобразований. Для HLS используется независимый эталон — модуль `colorsys` стандартной библиотеки Python: он принимает и возвращает нормированные значения 0–1. Само приложение `colorsys` не использует: формулы реализованы явно в `colors.py`.
