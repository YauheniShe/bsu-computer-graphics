# Базовые растровые алгоритмы

Каждый алгоритм возвращает список `Pixel(x, y, alpha)`. У четырёх обязательных алгоритмов `alpha=1`. Если передать список `trace`, в нём сохраняются промежуточные значения для таблицы шагов. Сам расчёт не зависит от Tkinter.

## Пошаговый алгоритм

Для `dx=x1−x0`, `dy=y1−y0` ведущая ось — та, у которой больше абсолютное приращение. Если `|dx|≥|dy|`, идём по X с шагом `sign(dx)` и каждый раз считаем:

```text
y = y0 + (dy/dx)·(x−x0)
```

Для крутого отрезка меняем X и Y местами. Полученную вторую координату округляем. При одинаковых концах возвращаем один пиксель. Это позволяет отдельно не делить на ноль у вертикальных отрезков.

## ЦДА

`L=max(|dx|, |dy|)`. Начинаем с `(x0, y0)` и после каждого пикселя прибавляем `dx/L` и `dy/L`. Всего получается `L+1` пикселей, включая концы.

Пошаговый метод заново вычисляет точку по уравнению. ЦДА использует предыдущую точку и сложение, поэтому может накапливать ошибку вещественной арифметики. В `nearest()` используется `floor(value+0.5+1e−10)`: половины округляются вверх, а маленький допуск предотвращает ошибку на значениях вроде `0.49999999999999994` при допустимых координатах.

## Брезенхем: отрезок

Пусть `a` — модуль приращения ведущей оси, `b` — второй оси. Начальная ошибка `d=2b−a`. После вывода текущего пикселя:

- если `d<0`, двигаемся только по ведущей оси и прибавляем `2b`;
- если `d≥0`, двигаемся по обеим осям и прибавляем `2(b−a)`.

Знаки приращений определяют направление движения. После подготовки используются целые числа, сложения и сравнения. При точном попадании идеальной линии между двумя центрами допустимы оба соседних пикселя. У Брезенхема при `d=0` выбран диагональный шаг; из-за этого в некоторых направлениях его результат отличается от округления вверх на половине. Оба результата находятся на расстоянии не более половины пикселя от линии.

Для `(0,0) → (13,8)`:

```text
d0 = 2·8−13 = 3
(0,0), d=3   → диагональ → (1,1), d=3+16−26=−7
(1,1), d=−7  → прямо    → (2,1), d=−7+16=9
(2,1), d=9   → диагональ → (3,2), d=9+16−26=−1
```

Полная таблица есть в отчёте и приложении. Для этого примера все три метода дают одинаковые пиксели.

## Брезенхем: окружность

Вычисляем один октант относительно центра: `u=0`, `v=R`, `d=3−2R`. Пока `u≤v`, добавляем восемь симметрий `(±u,±v)` и `(±v,±u)`, сдвинутых на центр окружности. Повторяющиеся координаты на осях и диагоналях удаляются.

```text
если d < 0: d = d + 4u + 6
иначе:     d = d + 4(u−v) + 10; v = v−1
u = u+1
```

В правых частях используются старые `u` и `v`. Радиус 0 даёт один пиксель. На примере `R=8` состояния `(u,v,d)` равны `(0,8,−13)`, `(1,8,−7)`, `(2,8,3)`, `(3,7,−11)`, `(4,7,7)`, `(5,6,5)`; всего 44 разных пикселя.

## Сглаживание по схеме Ву

Вместо одного ближайшего пикселя выделяем два соседних. Для точной второй координаты `y`, `j=floor(y)`, `f=y−j`:

```text
alpha(x,j)   = 1−f
alpha(x,j+1) = f
```

Веса складываются в 1. Их взвешенная координата совпадает с идеальной линией. У крутых отрезков оси меняются местами. В коде дробная часть получается через `divmod` целого числителя на длину: так нет накопления ошибок и одинаково обрабатываются отрицательные координаты. Нулевые веса не добавляются.

Это двухпиксельная схема Ву для целочисленных концов. Конечные пиксели закрашиваются полностью; обработка произвольных дробных концов с частичным покрытием не реализована. Цвет на белом фоне: `alpha·цвет_линии+(1−alpha)·255` по каждому каналу. Это учебное смешивание экранных RGB-значений без гамма-коррекции.

## Сетка и экран

Центр пикселя `(x,y)` находится в целой точке. Его клетка — `[x−0.5,x+0.5) × [y−0.5,y+0.5)`. При масштабе `s` и экранном начале `(ox,oy)`:

```text
X = ox + x·s
Y = oy − y·s
```

Минус нужен потому, что экранная Y растёт вниз. Прямоугольник пикселя имеет углы `(X−s/2,Y−s/2)` и `(X+s/2,Y+s/2)`. Оси проходят через центры, линии сетки — по границам клеток. Пунктир строится в той же системе координат. Масштаб и сдвиг меняют только отображение, список пикселей остаётся прежним.

## Что измеряет benchmark.py

`perf_counter_ns()` измеряет создание полного списка пикселей, включая проверки аргументов и Python-объекты. Отрисовка, заполнение `trace`, таблицы и файловый ввод-вывод не входят в замер. Перед замерами выполняется прогрев; сборка циклического мусора отключается только внутри измеряемого участка и затем восстанавливается.

Для каждой длины `L∈{100,500,1000}` используются восемь направлений с отношением меньшего приращения к большему `0.4`. Каждая серия содержит 40 повторений восьми отрезков, то есть 320 вызовов. Для радиусов `R∈{40,200,400}` выполняются 40 вызовов на серию. Всего пять серий, результат — медиана времени вызова. JSON также содержит минимум, максимум, число пикселей и время на пиксель.

Сложность трёх несглаженных отрезков и Ву — `O(L)`, окружности — `O(R)`. Память под возвращаемый список линейна. Ву выдаёт до двух пикселей на шаг, окружность — до восьми, поэтому время разных примитивов нельзя сравнивать только по числу вызовов. Полученные числа относятся к этой реализации Python и выбранным входам.
